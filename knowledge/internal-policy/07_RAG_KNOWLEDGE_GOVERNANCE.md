## 지식 계층

1. 현행 법령·감독규정
2. 감독·공공기관 공식 지침
3. 금융회사 승인 내부규정·매뉴얼
4. ALZ's well 승인 자체 정책
5. 개별 금융회사 공개 사례자료

충돌 시 상위 계층과 최신 효력 문서를 우선한다. 공개 사례자료로 가상 기관의 조건을 확정하지 않는다.

## 문서 상태

- 반입 실행: `RECEIVED → QUARANTINED → REVIEWED`
- 승인: `DRAFT → IN_REVIEW → APPROVED/REJECTED`
- 검색 생명주기: `PENDING_ACTIVATION → ACTIVE → SUPERSEDED/EXPIRED/RETIRED`
- 물리적 폐기: 별도 보존·폐기 승인과 `DISPOSED` 감사기록

`SUPERSEDED`는 새 버전 대체, `EXPIRED`는 효력기간 종료, `RETIRED`는 운영상 철회를 뜻한다. `DISPOSED`는 검색 생명주기 상태가 아니며 원문·파생물·백업의 실제 폐기와 증적을 별도로 관리한다.

현재 코드 카탈로그의 외부 노출 상태는 `APPROVED`, `EXPIRED`이며, 세부 승인·생명주기 분리는 P1 계약과 V40에서 관리한다. 승인 전 문서는 검색 인덱스에 넣지 않는다.

## 필수 메타데이터

`documentId`, `title`, `issuer`, `documentType`, `version`, `effectiveFrom/To`, `classification`, `allowedRoles`, `sourceUrl`, `sourceHash`, `approvedBy/At`, `checkedAt`, `status`, `supersedes`, `usageRights`를 기록한다.

## 전처리·검색

- 원문 보존본과 파생 텍스트·chunk를 분리한다.
- 표·조항·제목 경계를 보존하고 문단별 출처 위치를 유지한다.
- 임베딩 모델·토크나이저는 검증된 내부 아티팩트만 사용하며 자동 다운로드를 차단한다.
- ACL과 효력기간을 유사도 검색보다 먼저 적용한다.
- 답변에는 최소 한 개의 활성 근거와 문단 인용이 필요하다.
- 검색 점수는 권위·최신성·문서유형 필터를 대신하지 않는다.

## 폐쇄망

문서 저장소, 파서, 임베딩, 벡터 DB, LLM, 로그·추적을 내부망에서 운영한다. 컨테이너 outbound를 기본 차단하고 외부 API 키를 배포하지 않는다. 원문과 벡터 인덱스를 암호화하며 백업도 같은 등급으로 보호한다.

## 악성 문서·인젝션

문서 안의 “이전 지시를 무시” 같은 문구는 데이터로 취급한다. HTML 스크립트, PDF JavaScript·첨부객체, 매크로, 외부 링크를 검사하고 위험 문서는 격리한다. 검색문맥은 시스템 정책을 변경하거나 도구 호출 권한을 부여할 수 없다.

## 감사

사용자·역할, 질의 해시, 필터, 검색 문서·문단, 문서버전, 모델·프롬프트 정책버전, 생성·폴백 결과를 기록한다. 원문 질의와 민감정보는 최소화한다.
