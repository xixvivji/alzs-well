# 장애·오답·보안사고 대응 절차

| 항목 | 값 |
|---|---|
| 문서번호 | AW-POL-012 |
| 버전 | 1.0-draft |
| 소유 역할 | 사고대응 책임자 |
| 승인자·연락망 | TBD |

## 사고 유형

- 가용성: LLM·벡터 DB·문서 저장소·애플리케이션 장애
- 품질: 허위 인용, 만료정보, 금지된 진단·상품권유, 잘못된 안내
- 개인정보: 과다 프롬프트, 무권한 검색, 로그·출력 노출
- 보안: 악성 문서, 프롬프트 인젝션, 계정탈취, 외부 egress
- 무결성: 문서·인덱스·감사로그 해시 불일치

## 즉시 조치

1. 고객 안전과 증거 보존을 우선하고 사고 ID를 발급한다.
2. 영향 기능을 비활성화하고 외부 전송·자동 배치를 차단한다.
3. RAG/LLM 장애는 `DeterministicCopilotAdapter`로 전환한다.
4. 문제가 된 문서·인덱스·모델 버전을 격리하고 마지막 승인본으로 고정한다.
5. 실제 금융피해 가능성은 금융회사의 기존 피해대응 절차로 상향한다.

## 분석

영향 사용자·기간·사건·문서·모델·출력, 데이터 유출 여부, 잘못된 상태변경 여부를 감사로그로 재구성한다. 원인 제거 전 모델 재시도나 문서 재색인을 반복하지 않는다.

## 복구 승인

패치, 회귀평가, 해시·ACL·egress 검사, 폴백 시험, 소비자보호·보안 공동 승인을 마친 뒤 단계적으로 복구한다. 잘못된 안내를 받은 사용자에게는 승인된 정정 절차와 사람 상담을 제공한다.

## 통지·사후조치

법정 신고·정보주체 통지 요건과 기한은 개인정보·준법 담당자가 판단한다. 사후보고에는 원인, 영향, 시간대, 조치, 미해결 위험, 재발방지, 정책·평가세트 변경을 포함한다. 운영 출력은 자동 재학습 자료로 사용하지 않는다.

## 등급·목표시간

SEV-1~3 분류와 탐지·대응·복구 목표시간, 연락망은 금융회사 운영환경 확정 후 `TBD`로 승인한다. 공모전 시연에서는 담당자 수동 전환과 템플릿 폴백을 필수 리허설한다.
