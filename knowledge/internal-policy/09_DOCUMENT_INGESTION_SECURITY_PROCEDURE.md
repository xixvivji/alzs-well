# 문서 반입 및 보안검사 절차서

| 항목 | 값 |
|---|---|
| 문서번호 | AW-POL-009 |
| 버전 | 1.0-draft |
| 소유 역할 | 지식관리자·보안관리자 |
| 승인자·시행일 | TBD |

## 반입 전

1. 공식 출처, 게시기관, 게시일, 원본 URL과 이용조건을 기록한다.
2. 반입 요청자가 목적·문서유형·예상 접근역할·효력기간을 제출한다.
3. 승인된 전송매체 또는 통제된 반입 게이트만 사용한다.

## 격리 검사

1. 파일명을 정규화하고 실제 MIME·확장자·크기 제한을 검사한다.
2. SHA-256을 계산하고 중복·변조 여부를 확인한다.
3. 악성코드와 압축폭탄을 검사한다.
4. PDF JavaScript·실행 동작·내장첨부, Office 매크로·외부 링크, HTML script·원격 리소스를 검사한다.
5. 암호화·손상·파서 오류 파일은 자동 반려 또는 수동 검토한다.
6. 개인정보·비밀정보·저작권·공공누리 조건을 분류한다.

위험 신호가 하나라도 있으면 `QUARANTINED`를 유지하고 색인·미리보기·LLM 입력을 금지한다.

## 내용 승인

- 업무 담당자: 내용의 관련성·최신성·효력 확인
- 준법/법무: 법적 성격과 표현 한계 확인
- 개인정보/보안: 등급·권한·처리위험 확인
- 지식관리자: 메타데이터·버전·대체관계 확인

동일인이 요청·검사·최종승인을 모두 수행하지 않는다. 공모전 단계의 담당자 실명은 `TBD`로 유지한다.

## 적재

승인된 원문은 변경 불가 영역에 저장하고 파생 텍스트를 별도 생성한다. chunk 수·파서·임베딩 모델·인덱스 버전·입출력 해시를 `knowledge_ingestion_run`에 기록한다. 샘플 문단을 원문과 대조한 뒤 `ACTIVE`로 전환한다.

## 현재 corpus 적용

`knowledge/official-source`의 93개 원문은 수집·해시 검증까지 완료된 보존본이다. 실제 RAG 색인 전 최신성, 이용조건, 악성객체와 승인자를 추가 확인해야 하며 README의 “반입 및 색인 전 필수 절차”를 따른다.
