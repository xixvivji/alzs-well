# 문서 최신성 검토·교체·폐기 절차

| 항목 | 값 |
|---|---|
| 문서번호 | AW-POL-013 |
| 버전 | 1.0-draft |
| 소유 역할 | 지식관리 책임자 |
| 승인자·시행일 | TBD |

## 검토 주기

| 문서유형 | 정기검토 | 수시검토 트리거 |
|---|---|---|
| 법령·감독규정 | 분기, 운영 확정 시 조정 | 개정·시행·폐지 공고 |
| 공공지원·금액·자격 | 월 또는 안내 전 확인 | 기준연도·예산·지역 변경 |
| 금융회사 내부규정 | 소유부서 지정 주기 | 승인 개정·업무사고 |
| ALZ's well 자체 정책 | 분기 및 출시 전 | 코드·서비스·모델·사고 변경 |
| 공개 사례자료 | 반기 | 페이지 폐쇄·조건 변경 |

주기는 운영 승인 전 `TBD` 성격의 초안이며 최신성 표시를 대신하지 않는다.

## 교체

1. 새 버전을 별도 문서 ID/버전으로 반입·검사한다.
2. 효력일, 변경 조항, 대체관계와 영향 서비스·평가케이스를 기록한다.
3. 승인 후 새 버전을 `ACTIVE`, 이전 버전을 `SUPERSEDED` 또는 `EXPIRED`로 원자적으로 전환한다.
4. 영향 chunk만 새 인덱스에 생성하고 전체 회귀평가를 수행한다.
5. 배포된 인덱스·문서 스냅샷 해시와 전환시각을 남긴다.

## 만료·긴급 철회

효력기간이 끝난 문서는 `EXPIRED`, 새 버전으로 대체된 문서는 `SUPERSEDED`, 오류·권한 문제·보안사고 등 운영 사유로 철회한 문서는 `RETIRED`로 전환하고 검색 후보에서 즉시 제외한다. 대체 문서가 없으면 답변을 만들지 않고 근거 부족과 공식 확인 경로를 반환한다.

## 폐기

`DISPOSED`는 검색 생명주기 상태와 분리된 물리적 폐기 결과다. 보존의무·법적 보류·감사 재현 필요성을 확인한 뒤 승인된 방식으로 원문, 파생 텍스트, 임베딩, 캐시와 백업을 처리한다. 메타데이터와 폐기 증적은 허용기간 동안 보존한다. 폐기는 지식관리자와 보안/준법 중 한 역할의 이중승인을 요구한다.

## 코드·문서 동기화

사유코드, 상태, 서비스 코드, 동의 범위가 바뀌면 SSOT, DB 제약, API 명세, 본 정책 세트, 평가세트를 같은 변경요청으로 갱신한다. 불일치 시 실행 코드는 안전상 권위가 되지만 출시는 중단하고 SSOT를 재조정한다.
