# 실서비스 준비도 기준

이 문서는 API 개수와 실서비스 준비도를 구분한다. ALZ's well의 API 카탈로그와 합성데이터
업무 흐름은 공모전 MVP 범위에서 충분하지만, 실제 금융서비스 전환은 아래의 독립된 승인
게이트를 모두 통과해야 한다.

## 준비도 단계

| 단계 | 허용 데이터·사용자 | 목적 | 현재 목표 |
|---|---|---|---|
| 로컬 개발 | 합성데이터·개발자 | 기능과 계약 검증 | 통과 |
| 공개 공모전 데모 | 합성데이터·익명 시연자 | 제품 가치와 장애 폴백 시연 | P1 보완 후 가능 |
| 사설 금융사 PoC | 가명·최소 데이터·승인된 임직원 | 업무 적합성·오탐·사용성 검증 | 미검증 |
| 실서비스 | 실제 고객정보·기업 임직원 | 금융회사 운영 | 미승인 |

## 실서비스 승인 게이트

### 1. 신원과 권한

- 고객·직원 기업 IdP, MFA, 계정 수명주기와 퇴직자 회수
- 역할분리, 최소권한, 긴급권한과 정기 접근권 재검토
- 서버가 검증한 서명 claim만 신뢰하고 브라우저 전달 신원 헤더는 신뢰하지 않음

### 2. 개인정보와 데이터 수명주기

- 처리 목적·법적 근거·동의·철회·보존기간·파기 절차 승인
- AI 입력 전 개인정보·계좌·연락처 탐지, 거부 또는 마스킹
- 운영 로그·백업·분석 데이터까지 동일한 분류와 삭제정책 적용

### 3. 데이터베이스와 감사 증적

- 런타임·migration·검색·ingestion 역할 분리와 권한 회귀검사
- 역할·정책·탐지 결과·승격·감사 terminal row의 불변성 보장
- 거절·폴백·사람 승인까지 변조 방지 감사이력에 포함

### 4. AI 신뢰 경계

- AI 응답을 신뢰하지 않고 Spring이 원 입력으로 수치·상태·인용을 독립 재검증
- 정책 무응답과 장애·인덱스 누락을 구분하고 허용된 경우에만 폴백
- 승인 모델·문서·인덱스 hash와 실제 검색 준비상태를 readiness에서 검증
- 진단·사기판정·자동 금융행위 금지와 사람 최종승인 유지

### 5. 운영 인프라

- Vercel과 AWS의 실제 배포 digest, 환경 승인, 비밀 회전과 OIDC 기반 배포
- Vercel WAF의 세션 생성 IP rate rule, 일반 API rate rule, Bot Protection과 Preview 보호 증적
- 다중 가용영역, 백업 복구, 관측성, 경보, 용량시험, 장애훈련
- 업무 EC2와 AI 계층 간 전송 암호화 및 RDS 강제 TLS
- RTO·RPO, 롤백, 사고대응과 증적 보존 검증

### 6. 제품 효과와 규제 검증

- 고령 고객·행원 대상 사용성 및 접근성 검증
- 정상·주의·오탐 실제 분포에서 정밀도, 재현율, 오탐률과 처리시간 측정
- 개인정보·신용정보·전자금융·금융소비자보호 관련 법무·준법 검토
- 외부 원문과 모델 artifact의 이용·재배포 권한 확인

## 출시 판정 원칙

자동 테스트 통과는 코드가 계약대로 동작한다는 증거다. 실서비스 승인은 실제 사용자,
실제 운영환경, 조직의 접근통제와 법무·준법 승인까지 포함한다. 따라서 API가 추가됐다는
이유만으로 준비도 단계를 올리지 않는다.

공개 공모전 데모는 합성데이터와 실행 없는 안내에 한정한다. 사설 PoC 또는 실서비스로
전환할 때에는 이 문서의 각 게이트에 담당자, 승인 증적, 검증일과 만료일을 연결한다.
