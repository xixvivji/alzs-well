# 프론트엔드 API 역할 매핑과 합성 운영 원칙

기준 브랜치: `develop`  
적용 범위: Next.js 프론트엔드와 공개 시연 환경

## 합성 데이터 운영 원칙

이 서비스의 회원·계좌·거래·알림·사건·감사 데이터는 모두 합성 데이터다. 그러나 화면과 API에서는 단순 샘플 카드가 아니라 다음 조건을 지키는 **운영형 데이터**로 취급한다.

- 300개 합성 회원은 서로 다른 로그인·세션·소유 데이터 범위를 가진다.
- 조회·수정·승인·철회는 실제 서비스와 같은 인증, 권한, 버전, 멱등성, 감사 흐름을 거친다.
- 고객 화면에는 고객 본인의 금융생활과 직접 관련된 기능만 제공한다.
- 행원 화면에는 고객 확인 이후의 사건 검토·근거·메모·후속관리만 제공한다.
- 관리자 화면에는 정책·알고리즘·감사·보존·합성 데이터셋 통제를 제공한다.
- 실제 금융망, 실명정보, 외부 연락, 송금·주문·대출 신청 같은 대외 실행은 연결하지 않는다.
- 합성 데이터라는 안전 고지는 유지하되, 화면 본문은 실제 금융서비스의 정보 구조와 업무 흐름으로 구성한다.

## 역할별 화면 배치

| 역할 | 대표 화면 | 연결 원칙 |
| --- | --- | --- |
| 고객 | `/banking/**` | 본인 계좌·거래·상품·동의·보호 설정과 도움 요청 |
| 보호업무 행원 | `/staff/cases`, `/staff/operations` | 사건 큐·상세·타임라인·근거·내부 메모·후속관리·의향 요약 |
| 탐지 관리자·준법 | `/staff/control-center` | 규칙·정책·알고리즘·기능 플래그·감사·보존 정책 |
| 공개 상태 | `/staff/system-status` | 민감정보 없는 준비상태·버전·AI 폴백 경계 |
| 시나리오 전용 | `/demo/**` | 정상·주의·오탐 시연의 세션 격리 실행 |

## 직접 화면에 노출하지 않는 API

다음 API는 미연결이 아니라 의도적인 간접 연결 또는 서버 전용이다.

- `POST /api/v1/auth/login`, `POST /api/v1/auth/token/refresh`, `POST /api/v1/auth/logout`: 브라우저가 Bearer token을 다루지 않도록 Next.js BFF만 호출한다.
- 데모 세션 capability 발급·폐기: demo BFF와 시나리오 런타임이 관리한다.
- 단일 리소스 상세 API: 목록에서 사용자가 대상을 선택했을 때만 동적으로 호출한다.
- 관리자 게시·롤백·데이터 적재: 공개 환경에서 자동 실행하지 않으며 권한·확인·감사 UI를 거친다.
- 외부기관 참고 API와 실제 금융 실행 API: 계약 카탈로그에 남기되 직접 실행 화면을 만들지 않는다.

## 이번 연결 범위

- 고객 계좌 화면: 계좌별 거래, 거래처, 부채, 정기납부 달력, 거래 분류, 금융 기억 메모, 납부 확인 알림
- 고객 상품 화면: 보유 대출 상세, 대출상품 조건, 관심종목, 첫 관심종목의 지연 시세와 차트
- 행원 운영 화면: 첫 우선 사건의 상세, 타임라인, 근거, 메모, 후속관리, 금융생활 의향 요약
- 관리자 통제 화면: 규칙·감사 이벤트 목록과 첫 대상 상세, 정책·알고리즘·플래그·보존 현황
- 시스템 상태 화면: 공개 health, core/AI/통합 readiness, config, version과 AI 템플릿 폴백 상태

API 연결률은 정적 문자열 개수만으로 완성도를 판단하지 않는다. 동적 상세 호출, BFF 전용 호출, 권한상 UI 비노출 항목을 분리하고 각 역할의 실제 업무 흐름이 끝까지 닫히는지를 우선한다.
