후속 업데이트: PR #182 develop 병합, AWS V77·v3.1 적재, 세 역할 BFF 검증과 정상·주의·오탐 리허설을 완료했다. 임시 권한은 회수했다. 실행 증적은 [v0.1.4 배포 기록](RELEASE_V0_1_4.md)을 따른다. 아래 보류 표기는 문서 점검 당시의 이력이다.

## AI 기능의 실제 역할

- 검색: Hash가 기본 설정이며 승인된 staging 구성은 Arctic-ko 1024차원 임베딩과 PostgreSQL/pgvector 검색을 사용한다. 모델 승인은 `STAGED_APPROVED`다.
- 금융생활 의향·쉬운 설명: 구조화 규칙·템플릿으로 초안을 만들고 고객 확인·승인 절차를 거친다. 음성 읽기는 프런트의 브라우저 기능과 구분한다.
- 장기 변화: FastAPI EWMA/CUSUM 분석과 요약·질문·체크리스트를 Spring이 재검증한다. 입력은 합성 금융데이터이며 실제 고객 분포의 효과를 입증하지 않는다.
- 행원 지원: 승인 근거 검색·인용과 템플릿 초안을 사용한다. 생성형 LLM 연결·운영 `APPROVED` 승격은 완료로 표시하지 않는다.

평가는 [AI 평가 안내](../ai-service/evaluation/README.md)의 데이터셋별 보고서를 따른다.
17건 합성 회귀, 27건 공식 근거 골든셋, 150건 검수 후보는 서로 다른 모집단이다.
과거 평가 수치를 합산하거나 이번 문서 점검에서 재측정했다고 표현하지 않는다.

## 이번 코드와 운영 상태

코드에 반영된 변경은 회원별 생활거래 확대, 접근성 글꼴·고대비 보완, 인증 갱신 안정화,
행원 인증 오류의 익명 시나리오 자동 전환 제거, 관리자 부분 실패 표시,
계좌·거래 비동기 요청 경쟁 방지, Tomcat 업데이트다.

`517781c`에서 `./gradlew clean test bootJar`는 성공했다. 기존 프런트 검증과 CI 결과는
해당 커밋·실행에 한정한다. 문서 갱신 중 전체 테스트나 배포 검증을 새로 수행한 것은 아니다.

사용자 요청으로 다음 작업은 보류 중이다.

1. PR #182 CI 최종 확인과 develop 병합
2. AWS 이미지 교체·V77 적용·PUBLIC v3.1 적재
3. 고객·행원·관리자 운영 E2E 재검증
4. develop → main 최종 릴리스·태그

기존 staging의 날짜별 배포 기록은 [배포 체크리스트](STAGING_DEPLOYMENT_CHECKLIST.md)에
보존한다. v3.1의 216,000건은 새 run 검증 전까지 운영 적재 완료 수치로 사용하지 않는다.
이전 버전과 새 fixture가 공존할 수 있으므로 전체 테이블 count 대신 run별 수량을 검증한다.

## 문서 사용 원칙

SSOT는 제품 목적·범위, API 명세는 계약, README는 실행 방법을 제공한다.
구현 여부는 코드·테스트, 배포 여부는 배포 기록에서 확인한다. 평가 보고서·승인된 지식 원문은
해당 시점의 증거이며 내용 변경 시 별도 버전·승인·해시 갱신이 필요하다.
이번 최신화는 제출용 PDF 작성, 공식 공지·법령의 최신성 재검토, 독립 검수 승인을 포함하지 않는다.
